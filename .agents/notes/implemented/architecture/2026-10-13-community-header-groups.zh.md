# Agent Note: Community 顶部展示分组

Status: implemented

[English](2026-10-13-community-header-groups.md) | 中文

## 问题

Community 浏览器顶部区分原生 Session 工具和第三方扩展，打包的 Desktop 则保留原有展示。共享操作 slot 同时包含这两类条目，其公开注册元数据无法确认可信的包归属。读取 React 内部结构或搬移 DOM 节点会让展示依赖渲染器的私有细节。

## 决定

List 注册项携带父组件定义的可选展示 `group`。已获授权的父组件通过 `group` 或 `excludeGroups` 筛选自己的 outlet。Community 顶部分别挂载一次互不相交的原生与扩展分组，并省略只读模式状态；Desktop 顶部仍不筛选。这一增量 API 不改变注册权限、priority 选择、Session scope 或卸载行为。

原生操作包声明自己的分组。未知且未分组的操作注册项仍可在“插件”中找到。分组是展示约定，不是扩展属于官方的证明。未来的原生条目需要显式声明分组，渲染器不会根据名称或图标猜测。

## 考虑过的替代方案

**读取私有 React 结构并移动 DOM。** 这会重现原注入适配对渲染器内部结构的耦合，并可能让节点脱离所属组件的生命周期。

**第二套原生操作注册表。** 这会重复注册，让 Session 工具进入单独的状态和生命周期路径。筛选现有列表可以保留原有数据源和组件处理函数。

**卸载已收起的扩展。** 每次关闭“插件”都会丢失组件局部状态。折叠入口让已注册扩展始终仅挂载一次，收起时隐藏其内容。

## 影响

渲染器的真实 SlotCore 集成测试覆盖筛选排序、未分组条目、fallback、销毁和未筛选渲染不变。组件测试保留原生计数语义并验证扩展折叠交互。浏览器布局与打包 Desktop 行为仍需各自的视觉检查，这些组件测试不等于设备验收。

父组件渲染多个筛选出口时，必须保证选择不相交。已有注册项的分组元数据可省略，因此无法自动将未知的未来官方操作归类为原生。
